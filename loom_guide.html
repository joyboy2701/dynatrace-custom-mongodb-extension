Loom Recording Guide

PostgreSQL Custom SQL → Dynatrace Grail logs (Extension 2.0)

Fresh Linux box (with psql) hosts the ActiveGate, builds & uploads the extension into a fresh Dynatrace account.

custom:postgres-custom-sql 0.1.13 log.source = oracle_custom_sql ~30–35 min filmed
PostgreSQL ──SQL(5432)──► ActiveGate (this Linux box) ──logs(443)──► Dynatrace Grail log.source = oracle_custom_sql
Assumes PostgreSQL is reachable from the Linux box. If the DB runs on the same box use DB_HOST=localhost; if remote, use its IP. Replace xxxxx, YOUR_PG_HOST with your values.

0 Pre-flight (do BEFORE recording)

  • Fresh Dynatrace tenant URL: https://xxxxx.live.dynatrace.com
  • Logged into Dynatrace in a browser
  • SSH access to the Linux box
  • PostgreSQL host / port / user that can create a table + password
  • DB values decided: DB_HOST, DB_NAME=demo, DB_USER=dtuser
  • Linux box has git, python3, psql, nc, wget

Quick check on the Linux box

git --version && python3 --version && psql --version && which wget nc

1 Intro ~45 sec

I'm deploying a custom PostgreSQL SQL extension to Dynatrace. On this fresh Linux machine I'll install an Environment ActiveGate, then build and upload an Extension 2.0 that runs read-only SQL against Postgres and ships results to Grail as structured logs. Fresh tenant, end to end.

2 Create API token ~2 min

  • Settings → Integration → Dynatrace API → Generate token (or Access tokens → Generate new token)
  • Name: extension-upload
  • Add scopes:
    • extensions.write — required
    • extensions.read — recommended
  • Generate → copy the token (starts with dt0c01.)
These are the Extensions 2.0 scopes — write and read extensions. The old PluginUpload scope is for Extensions 1.0 and won't work.

3 Install Environment ActiveGate ~6 min

In the browser

  • Deploy Dynatrace → ActiveGates → Download ActiveGate
  • Type: Environment ActiveGate, OS: Linux, arch x86-64
  • Copy the one-line wget … .sh install command

On the Linux box

bash
# paste the command from the UI (token embedded in the URL):
wget -O Dynatrace-ActiveGate-Linux.sh "https://xxxxx.live.dynatrace.com/api/v1/deployment/installer/gateway/unix/latest?arch=x86&..."

chmod +x Dynatrace-ActiveGate-Linux.sh
sudo ./Dynatrace-ActiveGate-Linux.sh

Verify services

bash
sudo systemctl status dynatracegateway
sudo systemctl status dynatraceremotepluginmodule
Both should be active (running). In the browser, the new gate shows Connected under Deploy Dynatrace → ActiveGates. Note its name.

4 Verify network to PostgreSQL ~1 min

bash
# remote DB:
nc -zv YOUR_PG_HOST 5432
# or if Postgres is on this box:
nc -zv localhost 5432
The ActiveGate must reach Postgres — confirming the path before we go further.

5 Get the repo + seed demo data ~3 min

bash
git clone https://github.com/Abyshah/postgres-custom-sql-dynatrace.git
cd postgres-custom-sql-dynatrace

chmod +x scripts/seed_demo_data.sh
export DB_HOST=YOUR_PG_HOST     # or localhost
export DB_USER=dtuser
export DB_NAME=demo

./scripts/seed_demo_data.sh     # prompts for DB password

Verify

bash
psql -h "$DB_HOST" -U dtuser -d demo -c \
  "SELECT status, count(*) FROM dt_demo_orders GROUP BY status ORDER BY status;"
Here's the seeded demo orders — pending, success and failed rows.

6 Python env + signing certificates ~5 min

bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

dt-sdk gencerts
ls -la ~/.dynatrace/certificates/

6a — Upload CA to Dynatrace Credential Vault (browser)

  • Search Credential vault → Add credential
  • Type: Public certificate, Scope: Extension validation
  • Upload ~/.dynatrace/certificates/ca.pem
Headless box? Pull the file to your laptop to upload it: scp user@box:~/.dynatrace/certificates/ca.pem .

6b — Same CA onto this ActiveGate

bash
sudo mkdir -p /var/lib/dynatrace/remotepluginmodule/agent/conf/certificates
sudo cp ~/.dynatrace/certificates/ca.pem \
  /var/lib/dynatrace/remotepluginmodule/agent/conf/certificates/root.pem
sudo chmod 644 /var/lib/dynatrace/remotepluginmodule/agent/conf/certificates/root.pem
sudo systemctl restart dynatraceremotepluginmodule
Vault CA and the ActiveGate root.pem are the same file — that's what makes the signature trusted.

7 Build + upload the extension ~3 min

bash
chmod +x scripts/build_custom_integration.sh
./scripts/build_custom_integration.sh
ls -la custom_integration/dist/

Set credentials & upload

bash
cp .env.example .env
# edit .env: DT_ENV_URL + DT_API_TOKEN (token from Scene 2)
nano .env

./scripts/upload_extension.sh
Expect Extension upload successful!. Verify in Hub → Extensions → PostgreSQL Custom SQL (custom:postgres-custom-sql 0.1.13).

8 Monitoring configuration ~5 min

On the extension page → Add monitoring configuration.

  • Scope: Environment; ActiveGate group: the gate from Scene 3

Queries — fast path (on the Linux box)

bash
./scripts/export_queries_json.sh

Copy the one-line output → paste into Advanced: queries JSON (leave the SQL list empty). Then Save → wait for status OK.

SQL is plain SELECT text — no wrapping quotes.

9 Verify in Grail ~3 min

Browser → Notebooks (or Logs), time range last 15 min.

dql
fetch logs, from: now()-15m
| filter `log.source` == "oracle_custom_sql"
| fields timestamp, `query.name`, `query.status`, `error.message`
| sort timestamp desc
| limit 30
Here's success status for connection_test, orders_by_status and the rest.

Show real data

dql
fetch logs, from: now()-15m
| filter `query.name` == "orders_by_status"
| fields timestamp, `result.status`, `result.order_count`, `result.total_amount`

Optional — live proof (insert a row, watch it appear)

bash
psql -h "$DB_HOST" -U dtuser -d demo -c \
  "INSERT INTO dt_demo_orders (status, amount, customer_name, region) VALUES ('PENDING', 500.00, 'LoomDemo', 'eu-west-1');"

Re-run the DQL after ~1–2 min.

10 Wrap-up ~30 sec

Fresh box to working extension: ActiveGate installed, certs trusted, extension uploaded and signed, monitoring configured, and structured Postgres logs landing in Grail. A colleague can repeat this from the repo README.
